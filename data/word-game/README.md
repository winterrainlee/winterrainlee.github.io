# 단어게임 어휘 데이터

## 목적

게임의 목표 어휘는 전술 기믹에 사용되는 단어와, 별도의 암기·복습 스테이지에서 익히는 단어를 분리하지 않고 하나의 전체 풀에서 관리한다.

현재 기준은 국립교육연구원(NAER)의 TBCL 三等七級詞語表 2025-04다.

- TBCL 4 / 4*: CEFR B1 목표 풀
- TBCL 5: CEFR B2 목표 풀
- 현재 추출 결과: B1 1,429개, B2 2,641개, 총 4,070개

## 분류 스키마

어휘를 왜 `공식 사용 상황 → 세부 주제 → 의미·학습·게임 기능`의 여러 층으로 관리하는지, 마을과 기믹을 왜 같은 분류로 고정하지 않는지에 대한 설계 설명은 [`VOCABULARY-SCHEMA.md`](./VOCABULARY-SCHEMA.md)에 정리한다.

핵심은 단어를 한 서랍에 넣는 것이 아니라, 전체 B1–B2 어휘를 보존하면서 세계·이야기·전술·일반 복습 스테이지에서 서로 다른 방식으로 다시 조합할 수 있게 하는 것이다.

## 초기 콘텐츠 기획

4,070개 전체를 먼저 정교하게 분류하기보다, 실제 게임 진행과 사용 빈도를 통해 초반에 반복해서 쓸 핵심 목표어를 먼저 검증한다.

- [`CORE-VOCAB-v0.1.md`](./CORE-VOCAB-v0.1.md) — 튜토리얼 이후 우선 사용할 B1–B2 핵심 목표어 150개
- [`POST-TUTORIAL-WORLD-v0.1.md`](./POST-TUTORIAL-WORLD-v0.1.md) — 첫 월드의 마을 구조, 자유/권장/필수 경로와 각 마을의 역할
- [`INITIAL-PROGRESSION-PLAN-v0.1.md`](./INITIAL-PROGRESSION-PLAN-v0.1.md) — 튜토리얼 종료 직후부터 세 자유 마을, 권장 지역, 첫 잠금 지역인 研究城까지의 실제 초기 진행 기획

`CORE-VOCAB`의 150개는 최종 범위를 줄이기 위한 목록이 아니라, 초반 콘텐츠를 먼저 제작하고 실제 플레이 로그를 얻기 위한 우선 풀이다.

## 파일

### `tbcl-b1-b2-master.csv`
사람이 검토하기 쉬운 전체 B1–B2 어휘표. 원자료 층이므로 게임 설계를 이유로 직접 수정하지 않는다.

### `tbcl-b1-b2-master.json`
웹앱 및 스테이지 생성 코드에서 읽기 위한 동일 데이터의 JSON 버전.

### `tbcl-b1-b2-source.json`
원자료 버전, 출처 URL, 생성 시각, 실제 추출 행 수를 기록한다.

### `word-game-overlay.json`
사람이 검토·확정한 게임 편집층. 한국어 뜻, 세부 주제, 의미 태그, 암기 우선순위, 적합한 스테이지 방식, 마을 후보, 기믹 태그 등을 여기에 추가한다.

### `word-game-classification-candidates.json`
전체 4,070개에 대해 자동 규칙이 만든 1차 assisted 후보 분류. `source_category`는 TBCL 원자료를 그대로 가져오고, `topic_tags`·`semantic_tags`·`mechanic_tags`는 프로젝트 후보값이다. 사람이 검토하기 전에는 확정값으로 취급하지 않는다.

### `classification-taxonomy.json`
프로젝트가 허용하는 세부 주제·의미·기믹·스테이지 방식의 기준표. 자동 분류 코드와 사람이 붙이는 태그가 같은 어휘를 쓰도록 한다.

### `CLASSIFICATION-REPORT.md`
자동 분류가 어느 정도를 잡았는지, 어떤 태그가 많이 붙었는지, 아직 검토가 필요한 범위가 얼마인지 보여주는 품질 점검 보고서.

### `VOCABULARY-SCHEMA.md`
분류 스키마의 목적, 3층 구조, 필드 의미, 데이터 분리 원칙과 실제 활용 예시를 설명한다.

## 현재 자동 분류 상태

규칙 기반 1차 분류(`2026-09-v0.2`)는 단어 표면형과 TBCL 상황만 사용한다. 따라서 보수적으로 후보를 제안하며, 다의어와 추상어를 억지로 채우지 않는다.

- 전체: 4,070개
- assisted 후보가 하나 이상 붙은 어휘: 462개
- 세부 주제 규칙 직접 일치: 286개
- 의미 태그: 194개
- 전술 기믹 후보: 144개

정확한 최신 수치는 `CLASSIFICATION-REPORT.md`를 기준으로 한다.

현재 개발 우선순위는 전체 자동 분류 확장이 아니라 `CORE-VOCAB-v0.1.md`의 150개와 초기 월드의 실제 플레이테스트다.

## 자동 분류와 사람 검토의 관계

1. `word-game-classification-candidates.json`은 후보 생성용이다.
2. 자동 후보는 `assisted` 상태이며 공식 분류가 아니다.
3. 사람이 단어의 뜻과 실제 게임 용도를 확인한 뒤 `word-game-overlay.json`에 확정값을 남기고 `reviewed`로 올린다.
4. 자동 규칙이 후보를 만들지 못한 단어도 master에서 삭제하지 않는다. 일반 어휘 학습 스테이지의 대상이다.
5. 자동 분류 규칙을 개선해도 사람이 확정한 overlay를 덮어쓰지 않는다.

## 설계 원칙

1. 모든 B1–B2 단어는 master에 남긴다.
2. 전술 기믹으로 쓰기 어려운 단어도 삭제하지 않는다. 이 단어들은 일반 암기·판별·문맥 스테이지에서 사용할 수 있다.
3. `mechanic_eligible`은 단어의 학습 중요도가 아니라 '판 위에서 직접 행동으로 표현하기 좋은가'만 나타낸다.
4. 공식 TBCL 분류와 프로젝트가 덧붙인 주제·의미·게임 태그를 구분한다.
5. 한 단어에 여러 주제·마을·의미 태그를 허용하고, `primary_village`는 콘텐츠 진행을 위한 대표 배치로만 사용한다.
6. 마을별 전술 스테이지는 overlay에서 후보를 뽑고, 일반 어휘 스테이지는 master 전체를 대상으로 난이도·빈도·학습 이력에 따라 뽑는다.
7. 원자료가 갱신되면 `Refresh word-game TBCL vocabulary` GitHub Actions 워크플로로 master를 다시 생성한다.
8. 분류 후보는 `Classify word-game vocabulary` 워크플로로 다시 생성하며, 사람이 확정한 overlay와 분리한다.
9. 초반 콘텐츠는 핵심 150개를 먼저 사용하고, 플레이 로그를 바탕으로 교체·확장한다.
